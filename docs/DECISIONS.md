# Decisions

One line per decision: what we chose, the alternative, and why.

| #   | Decision                                                                                           | Alternative                                    | Why                                                                                                                                                                                                                                                                                |
| --- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | pnpm workspaces + Turborepo                                                                        | Nx, or npm workspaces alone                    | Turbo is small enough to explain fully; pnpm's strict `node_modules` catches undeclared dependencies, which matters for published packages.                                                                                                                                        |
| 2   | One monorepo for all packages and apps                                                             | One repo per package                           | The packages depend on each other and change together; one PR can span them, and one CI run proves they still fit.                                                                                                                                                                 |
| 3   | Turbo tasks: `typecheck` and `test` depend on `^build`                                             | No dependency, resolve to sources              | Consumers import the built output, exactly as npm users will, so we catch broken `exports` maps early.                                                                                                                                                                             |
| 4   | `.nvmrc` = 24, `engines.node` >= 22.19.0                                                           | Pin one version everywhere                     | Develop on current LTS; the floor is the MCP Inspector minimum, so the MCP server stays usable by others.                                                                                                                                                                          |
| 5   | `packageManager` field pins pnpm 11.18.0                                                           | Leave unpinned                                 | Same pnpm locally and in CI, so the lockfile does not churn.                                                                                                                                                                                                                       |
| 6   | Prettier run on its own (`format`, `format:check`)                                                 | Prettier as an ESLint plugin                   | Faster, and style rules stay separate from correctness rules.                                                                                                                                                                                                                      |
| 7   | `.gitignore` ignores `.env` and `.env.*` but allows `.env.example`                                 | Ignore only `.env`                             | Also covers `.env.local` and similar variants.                                                                                                                                                                                                                                     |
| 8   | `* text=auto eol=lf` and Prettier `endOfLine: lf`                                                  | Default per OS                                 | Developed on Windows, run in Linux CI; one line ending avoids noisy diffs and lint failures.                                                                                                                                                                                       |
| 9   | Web apps use TanStack Start, not Next.js                                                           | Next.js App Router                             | Chosen by the author. Affects the tsconfig preset and ESLint config for the apps.                                                                                                                                                                                                  |
| 10  | Docs-only coding rules in `docs/CODING_RULES.md`, enforced later via ESLint                        | Rules only in prose                            | A rule that is not checked by a tool drifts.                                                                                                                                                                                                                                       |
| 11  | TypeScript pinned to ~6.0.3                                                                        | Latest (7.0.x)                                 | TS 7 is the native compiler and its `typescript` package has no JS compiler API (my preset test failed to compile against it); `typescript-eslint` also declares support only below 6.1. TODO: revisit when typescript-eslint supports 7.                                          |
| 12  | ESLint and `@eslint/js` pinned to ~9.39.5                                                          | Latest (10.x)                                  | `eslint-plugin-react` declares peers only up to ESLint 9.7 (`pnpm peers check` flagged 10). TODO: revisit when the plugin declares ESLint 10 support.                                                                                                                              |
| 13  | Shared tool versions in a pnpm catalog (`catalog:`)                                                | Version in every package.json                  | One TypeScript, ESLint and Vitest version across the repo, changed in one place.                                                                                                                                                                                                   |
| 14  | Two tsconfig presets: `base` and `react`                                                           | A preset per package type (node, library, app) | Only DOM and JSX differ so far; add presets when a real difference appears.                                                                                                                                                                                                        |
| 15  | Presets set `noEmit`; tsdown does the building                                                     | tsc emits output                               | One build tool, so `tsc` only ever answers "does it type-check".                                                                                                                                                                                                                   |
| 16  | `strict`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax` on; `exactOptionalPropertyTypes` off  | Turn everything on                             | The first three catch real bugs cheaply; `exactOptionalPropertyTypes` clashes with many library typings. TODO: reconsider per package.                                                                                                                                             |
| 17  | eslint-config source is plain JS with named exports, tests in TS                                   | Write the config in TypeScript                 | ESLint loads JS directly, so there is no build step before linting.                                                                                                                                                                                                                |
| 18  | typescript-eslint `strict` (not type-aware)                                                        | `strictTypeChecked`                            | Faster and needs no tsconfig wiring for config files. TODO: consider type-aware rules later.                                                                                                                                                                                       |
| 19  | Test files may have long functions; `*.config.*` files may default-export                          | Apply every rule everywhere                    | `describe` blocks wrap many cases, and tools such as Vite require a default export.                                                                                                                                                                                                |
| 20  | Rules are tested by linting snippets through the ESLint API                                        | Trust the config                               | Proves each rule in CODING_RULES.md actually fires, and that clean code passes.                                                                                                                                                                                                    |
| 21  | Config packages are `private: true`                                                                | Publish them                                   | Internal tooling; Changesets will never version them.                                                                                                                                                                                                                              |
| 22  | tsdown builds the libraries                                                                        | tsup                                           | You told me tsup is no longer maintained (I had picked it first because the npm metadata showed no deprecation; I did not verify maintenance). tsdown emits ESM, CJS and declarations from one config. Its ESM output is `.mjs` and `.d.mts`, so the exports maps use those names. |
| 23  | Ship ESM, CJS and type declarations                                                                | ESM only                                       | CommonJS consumers (`require`, Jest setups, older tooling) still exist; one tsdown config emits both.                                                                                                                                                                              |
| 24  | Separate `.d.mts` and `.d.cts`, with `types` nested inside each `import`/`require` condition       | One shared `.d.ts`                             | TypeScript resolves types per module format; a mismatch makes types claim the wrong format.                                                                                                                                                                                        |
| 25  | `"type": "module"`: `.mjs` is ESM, `.cjs` is CJS                                                   | `"type": "commonjs"`                           | ESM-first, and file extensions state the format unambiguously.                                                                                                                                                                                                                     |
| 26  | `exports` map is the contract; `main`, `module` and `types` kept for legacy resolvers              | `exports` only                                 | Older resolution (`node10`) ignores `exports`; keeping the fields makes it resolve too. `./package.json` is exposed for tooling.                                                                                                                                                   |
| 27  | `files: ["dist"]` and `sideEffects: false`                                                         | Publish the whole folder                       | Small tarball, and bundlers may drop unused exports. TODO: confirm each library really is side-effect free as it grows.                                                                                                                                                            |
| 28  | `check-package` task (publint + attw) depends on `build`                                           | Eyeball the exports map                        | Tests what npm users get, across node10, node16 (CJS and ESM) and bundler resolution.                                                                                                                                                                                              |
| 29  | `index.ts` only re-exports; code lives in named files                                              | Code in `index.ts`                             | The public API is one short file, so accidental exports are visible in review.                                                                                                                                                                                                     |
| 30  | Each library owns its `package.json`, `tsdown.config.ts` and tsconfig, generated from one template | A shared tsup config package                   | Four small files per package are clearer than another package to maintain. Revisit if configs diverge.                                                                                                                                                                             |
| 31  | pnpm `allowBuilds: esbuild: false`                                                                 | Allow esbuild's install script                 | Build and tests work without it, so we grant no install-time code execution. TODO: re-check on esbuild upgrades.                                                                                                                                                                   |
| 32  | Libraries start at version `0.0.0`                                                                 | `0.1.0`                                        | Changesets will decide the first bump from a change note.                                                                                                                                                                                                                          |
